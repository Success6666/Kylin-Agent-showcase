# 告警、飞书与人工处置

后台监控负责采样、告警状态、防抖、通知与恢复跟踪。Agent 研判由操作人员在平台或飞书主动发起，通知启用和页面刷新保持采样流程。

## 采样与通知

后台监控默认连续两次不同采样确认异常，连续两次正常采样确认恢复；严重资源异常可立即触发，节点不可达继续按采样确认。重复、缓存及乱序采样按时间处理，防抖状态持久保存。

飞书卡片展示节点、级别、状态、采样时间、告警 ID 和 Trace。尚未生成方案时显示等待研判，操作人员生成后更新研判和进展。业务恢复由后续监测确认，手动关闭显示“已关闭”。

## 从生成方案到执行

1. 操作人员点击“生成处置方案”，服务端核验账号与节点权限，调用只读 Agent 检查现状并提出动作、风险、回退和验证标准。
2. 卡片展示一个待批动作的工具、参数、节点与风险；批准后与网页共用动作版本校验、单次派发令牌和 Harness。
3. 后续动作逐个批准，执行结果与进展通过卡片和 Trace 返回；拒绝动作记录身份和审计。

敏感参数或较长动作转到网页核对。告警轮次、来源群、消息、账号、配置、权限、方案版本与有效期在执行前重新核验。

## 回调与恢复

回调验证飞书签名、令牌和加密内容，重复回调与重复点击关联单一处理记录。消息使用持久化 Outbox、轮次去重、固定 UUID 和临时错误退避重试。

重启后已进入执行的请求显示“待核对”，操作人员结合 Trace 与业务状态继续处理。当前通知存储采用单控制节点，多副本共享存储和执行租约列为后续扩展。

本次回归覆盖旧自动研判配置、飞书启用组合、采样 API、生成方案、审批与回调检查。
