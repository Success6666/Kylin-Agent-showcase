# 运维处置与恢复闭环

Agent 自主选择诊断、检索、提问、变更和验证，Harness 管理授权、预检、锁、逐动作审批与执行证据。管理员配置受信服务别名和凭据引用，模型使用当前节点可用工具。

## 诊断与配置变更

业务健康检查覆盖状态、响应内容、时延、依赖端点、Prometheus 指标、连续成功次数与截止时间。前后比较引用节点签名证据 ID，恢复状态由业务检查记录。

`config_patch_preview` 生成精确替换 diff，冻结目标哈希与版本；`config_patch_apply` 通过预检、审批和语法检查后原子写入，保留权限与回滚记录。服务重载单独审批，随后验证业务。

## 数据库与备份恢复

数据库诊断使用固定只读语句。PostgreSQL 单会话恢复先读取连接信息，审批后按允许用户、应用名及 `backend_start` 绑定目标，执行后复查连接和业务状态。

备份预览校验真实归档，冻结应用目录和配置哈希。恢复可先进入隔离目录验证文件或 SQLite 断言，激活恢复要求应用停机，原子替换并保留旧版本。回退单独审批并核对当前版本，Agent 自身数据采用停机后的独占租约恢复流程。

## 分批变更与调查记录

`staged_rollout` 冻结逐节点变更、回退、健康配置与批大小。首节点完成且取得变更后健康证据，再开放下一批；执行或健康检查失败时暂停后续批次。回退 ID 从实际结果绑定，回退继续逐动作审批。

`investigation_update` 保存目标、事实、假设、排除理由及未解决问题，事实引用当前任务真实 evidence_id。依赖图分别展示管理员配置、实时探测和近期审计变更。

完成后，经执行与健康证据检查生成待审经验，再进入管理员审核与知识检索，见 [知识与记忆](rag-knowledge.md)。

本次回归覆盖 HTTP 波动、版本冲突、审批拒绝、文件回滚、SQLite 恢复、进程租约、分批变更和脱敏。真实模型的 Nginx、日志、PostgreSQL 故障实验保留历史结果，最新实现复验待完成，见 [评测说明](evaluation.md)。
