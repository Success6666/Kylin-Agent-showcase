# Git 历史中的开发取舍

以下按主项目 Git 提交正文、差异和当前实现整理。日期为提交时间；2026-10-17 的 v1.0.0 集成提交同时纳入此前开发的交互、场景集、处置和记忆能力。

## 从固定规划到原生工具循环

**2026-08-22 · `dd066a1` → 2026-10-17 · `84e8040`**

8 月版本引入 IntentGraph / GoalNode，显式描述多目标、依赖关系、澄清状态和图哈希，并按阶段发现工具。这种结构便于检查动作覆盖、恢复计划和关联审批，维护成本是分类、计划与运行时需要持续同步。

10 月主链路调整为原生 function calling：原始请求和历史进入主模型，模型根据观察决定继续调用、检索、提问或回答。按需工具发现保留，固定意图元数据与 Plan 继续用于兼容存储，权限、预检和审批由 Harness 管理。

开发取舍是把处理顺序交给模型，把执行资格和证据核对留在确定性运行时。上下文最多保留 12 个完整工具声明，以减少大目录注入；模型可按需重新加载。相应成本转到工具说明、循环状态、调用结果配对和完成证据检查。

## 多协议共用持久执行生命周期

**2026-08-08 · `f59e046`**

REST / A2A 请求从各自处理逻辑转入 `ChatExecutionService`，共用 canonical 请求指纹、single-flight、owner token、租约心跳、取消和结果复用。

选择持久执行账本，是为了解决跨协议重试、worker 退出和终态重复写入。它增加了状态迁移与租约恢复逻辑，同时让同一请求的所有权、取消及最终结果可以追踪。SSE 和后续交互继续使用统一生命周期。

## 有界并发与可靠终态

**2026-08-08 · `7a56252`、`290e968`**

SSE 从每请求 daemon thread 调整为固定 worker 池和有界队列，终态、审批、错误与取消独立可靠缓存，普通阶段事件允许合并。队列容量耗尽显式返回状态，并记录 dropped / coalesced / rejection 指标。

文件下载从 Base64 缓冲调整为流式响应，支持 Range 与客户端取消。取舍是接受明确背压和分块实现成本，换取稳定的线程数、内存使用和终态记录。

## 通用治理由独立 SDK 负责

**2026-08-08 · `2dc44cd`、`35463b7` → 2026-08-09 · `4c4ec11`**

审批、Schema、持久幂等、UNKNOWN 和审计迁入 `agent-runtime-governance` v0.9.1，原实现移到显式 legacy fallback。Adapter 继续绑定 Kylin 工具、节点身份和公开结果，CI 增加专项与通用回归。

独立 SDK 让治理规则集中维护，项目保留业务注册与权限语义。成本是适配层、版本锁定和两侧语义回归；依赖固定到 `4cfb9ccc`，便于镜像与控制面使用一致制品。

## PostgreSQL checkpoint 与七服务部署

**2026-08-13 · `fb7adc2`、`1f86c69`**

共享 PostgreSQL checkpoint 纳入恢复链路，并成为龙芯交付必需镜像。当前龙芯 Compose 包含面板、认证、控制面、两个节点、RabbitMQ 与 PostgreSQL，共七个服务。

任务恢复需要保存模型会话、审批状态和已执行动作。采用独立 PostgreSQL 增加一个持久服务及镜像验收，同时提供跨运行时 checkpoint；SQLite 继续承担 Outbox、任务、审计和知识等存储职责。集成测试模拟变更后崩溃，再由第二个运行时恢复，核对副作用次数。

## 按平台选择文档模型

**2026-08-23 · `684bafc`**

非 LoongArch 开发配置接入原生 Docling 扩展模型和离线制品校验，LoongArch 继续使用条件化 ONNX 部署路径。文档结构与切块接口统一，模型运行时按平台提供能力。

这一选择保留较丰富的开发文档处理能力，同时集中维护龙芯可部署的 ONNX 制品。成本是两套依赖配置、模型缓存与能力检查；固定 revision 和 SHA-256 用于制品复现。

## 评测从规模清单转到实际场景和测量记录

**2026-10-17 · `84e8040`**

旧集包含模板枚举、配对轨迹、单工具投影与故障规格。新 `agent_ops_zh_v1` 按六维度各 150 条组织，正文独立编写，页面默认显示 900 条当前数据及匹配场景哈希的测量记录。

数据量、机械检查、业务复核、RAG 资料源召回与真实服务恢复分别记录。这样可以追踪具体测量对象和修订后的样例，代价是逐条场景哈希、原始试跑保存和独立复核工作。完整 Agent 实测与业务复核继续推进。

## 经验归纳复用原审核与版本体系

**2026-10-17 · `84e8040`**

处置完成并取得变更后健康证据时生成待审经验。归纳、来源、生命周期和状态事实复用原经验库及 SQLite 辅助账本，管理员沿用修订、审核、发布流程。

选择保留单一审核链，降低知识发布和权限维护的重复工作。自动归纳要求至少三个独立已审核案例，核心上下文最多 2,400 字符、6 项，健康事实有效期 60 秒。成本是来源失效传播、检索资格、缓存复核及冲突时间窗维护。

## 长任务状态与告警主动研判

**2026-10-17 · `a635d05` → `ec62ccc` → `ee3a289` → `a0ec2e9`**

这组提交保留了一次尝试和回滚：`a635d05` 调整旧 ReAct 的硬预算，`ec62ccc` 随后撤回该修改；`ee3a289` 在飞书方案结果中区分待审批、已完成、等待输入和未完成，并增加原生循环旧 Token 配置回归。

当前原生循环记录用量与轮数，使用相同错误和相同观察控制停滞。`a0ec2e9` 将监测调度与采样 API 调整为采集、告警和恢复，Agent 由平台或飞书操作人员主动触发。

取舍是持续采样与人工发起方案分工，模型成本由显式处置请求产生。操作人员需要先生成方案，再逐动作审批；平台与卡片共用任务、权限和证据记录。
